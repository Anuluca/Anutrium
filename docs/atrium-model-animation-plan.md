# ATRIUM 路卡模型后续动作实施计划

- 记录日期：2026-10-27。
- 状态：待实施；本轮仅保存方案，不制作跑步、战斗等动作。

## 1. 当前资源与限制

- 原始资源：`scripts/assets/lucario/lucario.glb`。
  - 已有一套蒙皮骨架，共 58 根骨骼。
  - 当前没有动画片段（AnimationClip）。
- 构建流程：`scripts/lib/prepareLucarioGeometry.ts` → `scripts/build-lucario-model.mjs`。
  - 当前会调整站立姿态、烘焙骨骼变形、合并及减面。
  - 网页加载的 `.bin` 主要保存顶点、法线、索引及自定义头部权重，不是完整骨骼动画资源。
- 运行入口：`src/utils/islandLucarioModel.ts`、`src/views/Home/templeScene.ts`。
  - 当前的转头、点头与站立展示不能直接替代全身骨骼动画。
  - 拍照模式已提供站立入口；后续动作资源准备完成后再扩展姿势列表。

## 2. 资源前置工作

1. 保存原始 GLB 和可编辑工程，保留骨架、绑定姿态与蒙皮权重（Skinning Weights）。
   - 先检查肩、肘、胯、膝、尾巴及耳部的变形；是否需要修正权重，需用动作验证。
   - 当前已有骨架，不预设必须重新绑定。
2. 在 Blender 中制作最小动作集，统一骨骼命名、坐标朝向、比例与角色原点。
3. 先采用原地动作（In-place），角色整体位移由应用控制；需要根运动（Root Motion）时另行设计。
4. 每个动作独立保存和命名，避免依赖文件中的动作顺序。

| 动作标识      | 用途          | 播放规则 | 首批验收重点             |
| ------------- | ------------- | -------- | ------------------------ |
| `idle`        | 默认站立/待机 | 循环     | 首尾衔接、脚底稳定       |
| `run`         | 跑步          | 原地循环 | 重心、膝肘、脚底滑动     |
| `battle_idle` | 战斗待机      | 循环     | 手臂与躯干穿插、尾巴变形 |
| `attack`      | 单次攻击      | 单次     | 起止姿态、结束后回到待机 |

## 3. 导出与加载方案

- 输出包含骨架、蒙皮及动画的 GLB；保留关节索引、权重和逆绑定矩阵。
- 动态减面方案必须保留蒙皮属性；当前静态烘焙流程不能直接作为动画模型的最终输出。
- 先交付一个包含 `idle`、`run` 的验证模型，再决定：
  - 将动作与模型打包在同一 GLB；或
  - 共用骨架，按需加载独立动作资源。
- 保留当前静态资源作为回退，验证动画路径后再决定是否替换默认展示。
- 上线资源沿用线上资源地址与版本管理，不引用开发者本机路径。

## 4. 运行时接入

1. 使用 `GLTFLoader` 加载蒙皮模型，通过动画混合器（AnimationMixer）管理动作。
2. 建立按稳定动作标识索引的配置：名称、资源、是否循环、播放速度、默认过渡时间。
3. `idle`、`run`、`battle_idle` 之间使用交叉淡化（Crossfade）；单次攻击结束后回到指定待机。
4. 将模型整体拖动旋转、相机缩放与骨骼动作分层管理。
5. 头部指针跟随单独作为姿态叠加层；拍照模式关闭指针跟随，避免覆盖动作中的头部关键帧。
6. 为拍照列表预留播放、暂停及固定某一帧的接口；资源未就绪时不显示无效动作。
