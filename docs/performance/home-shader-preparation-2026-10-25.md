# B1：按入口与状态分批准备着色器

日期：2026-10-25。对应 [3D 审计 B1](../research/3d-performance-audit-2026-10-24.md)。基线包含已完成的 A1–A7，预热后为 95 个程序；原始审计中的 43 个程序属于更早版本。

## 实现

| 入口 | 显示前准备 | 入场期间继续准备 |
| --- | --- | --- |
| 首页、Island | 0 盏聚光灯，常态与渐隐队列、实际裁切槽位 | 1 / 2 盏灯的交互状态 |
| 四柱、花花小窝聚焦入口 | 0 / 1 盏灯的相同状态 | 2 盏灯的快速交接状态 |

- 首批完成后释放加载覆盖，定位入口目标并开始模型渐显。剩余状态按 `requestIdleCallback` 分批准备，带 50ms 超时，缺少该 API 时使用定时任务让出主线程。
- 交互开放统一等待入场动画与必要状态全部完成。首次聚焦、扫描及快速切换继续使用已准备程序，避免把编译移到第一次点击。
- 主模型、当前宠物、环境、标签及共享 GPU 数据完成一次上传。后续程序预热不再在模拟灯数下整场景重复绘制，也不批量生成所有无光照材质的灯数组合。
- 光池虽然使用 Basic 材质，首次显示的缓存键仍包含灯数，针对性准备 1 / 2 盏灯组合；线材质保留同样的缓存键覆盖。其余无光照材质复用已初始化程序。
- 两种队列的快照同时更新实例批次，覆盖建筑、底座、角色的常态与渐隐，保留既有双面策略。
- 快速入口先设置入场低头基准、再定位目标，保持四柱 0°、Island 5°、首页及宠物 10°的既有低头角度。页面 ready 回调按最后一次导航请求校正选择，包含加载期间取消聚焦。

## 后台编译隔离

- 使用独立材质快照、只读几何视图和灯光场景，复用几何、纹理、环境贴图和 uniform。可见场景的透明度和灯光数量不随预热改变。
- 本地 Three.js r182 的 `compileAsync` 在轮询时读取材质 `currentProgram`。快照避免可见帧重写待编译程序引用。
- `compileAsync` 的提交阶段同步执行。裁切槽数只在这个阶段临时设置；异步等待前恢复全局裁切、裁切内部状态和原渲染目标。
- 建立裁切状态使用 1×1 离屏空场景，不清空可见帧缓冲。
- 离场取消尚未执行的空闲任务，已提交编译完成后统一释放程序引用、快照和离屏目标，沿用已有 Renderer 释放顺序。
- 代价：预热快照增加 JavaScript 材质对象，保留到场景释放以持有未首次使用的程序；几何和纹理不为快照重复上传。
