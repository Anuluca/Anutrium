# Floratrium 页面架构与性能审查

- 日期：2026-10-15（Asia/Shanghai）。
- 范围：首页 `sprigatito` 聚焦模块、精选相册、全量媒体分页、共享媒体画廊、R2 列表接口及本地开发适配。
- 保留现有路由、视觉布局、主题、交互动画、线上 R2 图片地址和预览组件。

## 1. 删除与复用

| 原有问题 | 处理 |
| --- | --- |
| `indexPages` 为生成页码串行请求后续全部分页，`includes` 又在每一步扫描已知游标 | 删除预扫描和独立索引请求控制器。正常接口使用 `totalPages` 直接计算页码游标；旧接口只发现下一页，不主动下载未访问的页。 |
| 相册组件混合网络、轮询、取消、分页状态与 DOM 布局 | 提取 `useFloraAlbum`；组件保留 DOM、动画和媒体连接释放。请求结果校验、重试、可见性监听及作用域清理由组合式函数统一处理。 |
| 每轮刷新对新旧媒体数组各做一次 JSON 序列化 | 按 `key/url/type` 短路比较；数据不变时保留数组引用，避免清空预览及重新绑定媒体观察器。 |
| 无读取用途的 strip 根节点 ref、重复加载状态、未使用的 collapse 文案、重复 v-if、重复 nextCursor 状态 | 删除，下一页可用性直接来自已知页码游标。 |
| 开发适配器和 Worker 各自构建媒体 URL、页码和分页响应；递归目录每层都排序 | 共享 `createFloraMediaPage`、媒体识别和分页常量。本地目录只在最终列表排序一次。开发插件改为 TypeScript，删除旧 `.mjs` 文件并更新唯一入口。 |

经引用检查，其余 Floratrium 页面、模型与数据文件均有实际调用，未删除仍被使用的模块。宠物只有两项，保留简单查找；没有为了使用 Map 而替换低频小数组操作。

## 2. 算法与请求优化

| 路径 | 修改前 | 修改后与证据 |
| --- | --- | --- |
| R2 全量键名扫描 | 每次翻页遍历全部 R2 列表，并执行 `sort().reverse()` | 按桶绑定对象与宠物使用 WeakMap/Map 缓存已完成的键名索引，TTL 为 15 秒。R2 已按键名排序，过滤后直接反转；索引构建由 O(N log N) 降为 O(N)。 |
| 四页 R2 分页回归 | 117 个原始对象、31 个一批，读取四页需要 16 次 `bucket.list` | 同一索引有效期内读取四页仅 4 次调用，减少 75%；104 个有效媒体全部保留，顺序及分页长度不变。该数字是测试夹具的调用次数，不是线上耗时。 |
| 旧接口页码建立 | 打开首页后递归请求整个相册 | 打开只请求当前页。已知 100 页时，打开第一页再直跳第 100 页只有两次请求；未提供总页数的接口仍支持上一页/下一页。 |
| 每批媒体加载状态查找 | 每个 load 事件调用 `items.some`，整批最坏 O(N²) | computed Set 建立一次，单次查找平均 O(1)，整批 O(N)；过期媒体事件不能写回当前列表状态。 |
| 缩略图解析 | 每次媒体加载状态改变后重新遍历渲染，并反复构造桌面/手机缩略图 URL | 共享媒体索引一次建立 Set、图片列表和缩略图 Map；状态更新复用解析结果。浏览器回归验证尺寸/加载状态更新产生 0 次额外 URL 构造。 |
| 精选条复制图片 | 每个副本的 load/error 都重复更新比例、遍历全部媒体并测量布局 | URL/宽高比去重，缓存缩略图 URL，同一轮更新合并测量。10 张已就绪图片各重发两次 load，额外宽度测量由原逻辑的 20 次变为 0 次。 |
| 15 秒轮询 | 无条件中断慢请求，可能持续取消并重下同一页 | 有请求进行时跳过安静刷新。收起、隐藏、切换宠物及作用域结束仍会取消请求；版本号阻止迟到响应覆盖新状态。 |
| 前端响应式开销 | 完整媒体数组深层响应式转换 | 使用 shallowRef 保存只整体替换的媒体结果，减少不必要的深层代理。 |

R2 的排序依据见 [Cloudflare R2 Workers API reference](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/#bucket-method-definitions)。缓存仅保存已完成的纯数据，不跨请求共享 Promise、响应体或进行中的 I/O；请求生命周期参考 [Cloudflare Workers context](https://developers.cloudflare.com/workers/runtime-apis/context/)。

## 3. 缓存与兼容性边界

- HTTP 响应继续 `no-store`，媒体文件仍直接请求线上 R2；没有本地代理、文件回退或预下载整册媒体。
- 键名缓存仅在当前 Worker 实例和桶绑定对象内复用，不保证跨实例命中；并发冷请求可能各自扫描，未共享跨请求 I/O。
- 每个桶最多保留两个固定宠物目录的索引。失败和不完整索引不入缓存，过期后重新读取。
- 新增或删除文件在 15 秒索引过期后的下一次页面刷新可见；页面现有轮询周期为 15 秒。
- 未提供总页数的旧接口按已发现的游标导航，不再通过后台预扫描支持未知页码跳转。
- 三维模型现有的下载去重、构图缓存、按需渲染和旧 GPU 几何释放机制已复查，未发现需要重复实施的优化。模型切换、投影缓存失效、停止渲染由现有回归测试覆盖。

- 已增加缓存过期、桶/宠物隔离、失败重试、重复 R2 游标、旧接口无预扫描、已知页码直接跳转、慢请求保留、迟到响应丢弃、作用域取消和重复图片事件测量检查。
