# B4：首页场景诊断显式开关

## 行为

- 开发与生产默认关闭诊断；不会因为 `DEV` 自动开启。
- 构建参数：`VITE_HOME_SCENE_DIAGNOSTICS=true`。默认值见 `.env.example`；现有服务不会被自动重启。
- 测试覆盖：在场景创建前，通过初始化脚本设置 `window.__ANUTRIUM_HOME_DIAGNOSTICS__ = true`。布尔覆盖值优先于构建参数，`false` 可强制关闭。
- 开关在 `createHomeTemple` 创建时读取一次，不在逐帧路径读取 URL、存储或响应式状态；已创建场景不会热切换。
- 依赖内部字段的 23 份测试显式导入 `tests/helpers/sceneDiagnostics.ts`，通过浏览器上下文初始化脚本开启；普通测试保持默认关闭。夹具也支持 `test.use({ sceneDiagnostics: false })`。

## 运行状态与诊断数据

保留离散运行状态：入场方式、布局与模型标识、入场阶段/完成、准备入口/着色器准备阶段、主题色、颜色模式、沉浸状态、当前宠物标识。CSS 与场景逻辑依赖的这些状态不受诊断开关影响。

关闭的诊断计算包括：

- 帧内数字格式化、数组拼接、颜色序列化、标签和宠物额外投影、宠物投影边界统计。
- 相机与模型姿态、扫描进度、环境材质/灯光、绘制次数、缓存命中及 GPU 对象统计的 DOM 发布。
- 原先独立于主诊断块的头疼/贴纸数据，以及加载阶段的扫描几何字节数、模型统计、宠物几何/倒影元数据、着色器数量、渲染分辨率统计。

头疼姿态与贴纸动画、模型扫描、实际点击区域、标题/时钟位置、模型锚点和镜头适配继续执行。不是将 `setStageData` 改为空函数：开关位于计算分支之前，避免先计算再丢弃结果。

## 实测

复用本地 `localhost:3000`，不启动新服务。同一 Chromium 场景、同一静止姿态、同一时刻，按关闭 → 开启 → 关闭同步渲染。仅测试时注入采样器，统计 `Number.toFixed` 与 `Vector3.project`，读取完整 1280×720 WebGL 画布像素。

| 状态 | 每次绘制数字格式化：开 → 关 | 每次绘制坐标投影：开 → 关 | 像素差异 |
| --- | ---: | ---: | ---: |
| 总览 | 81 → 0 | 2 → 0 | 0 / 921600 |
| 主模型聚焦 | 81 → 0 | 8 → 6 | 0 / 921600 |
| 宠物聚焦 | 85 → 0 | 2 → 0 | 0 / 921600 |

主模型聚焦保留的 6 次投影用于实际锚点，未被关闭。该统计是静止姿态采样；运镜、重排和点击投影仍可能产生必要的格式化或投影。此处不推导整站 FPS 或 GPU 收益，诊断代码仍可在显式开启后执行。

## 验证

- 桌面与移动端默认关闭场景：入场完成、加载状态、主题切换、主模型聚焦及地平线位置正常，诊断字段不发布。
- 显式开启后：几何统计、相机数据正常发布；总览、主模型与宠物聚焦的同步开关像素比较一致。
- 现有扫描、头疼、灯光与缓存通过显式诊断夹具运行，12 项回归全部通过。
- B4 专项 3 项通过、1 项按设备跳过；23 份测试共 256 条用例可正常收集（未声称全部执行）。
- 定向 ESLint 与 Vite 构建通过。
- 全量类型检查仍有既有 `WorkCard/index.vue:102`、`Craft/CraftContent.vue:91` 两处 VueUse 参数类型错误。
