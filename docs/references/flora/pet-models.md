## 原始来源

- 新叶喵的模型及对应战斗待机 / 睡眠动画：用户提供的 `Downloads/romfs`。
- 大狼犬《朱紫》DLC1 原始模型、骨架、战斗待机 / 睡眠循环首帧及 BNTX 贴图：[RTB 的资源帖](https://archive.vg-resource.com/thread-25872.html)中的[公开资源目录](https://mega.nz/folder/elJhVC5D#NU-yzmXuTlsIIzXAMLKVaA)，分别来自 `SV-PokeDLC1.zip` / `SV-PokeAnimDLC1.zip`。
- 研究时下载的 [XY 大狼犬资源](https://models.spriters-resource.com/3ds/pokemonxy/asset/290949/)不包含动画，最终未作为运行时输入。
- TRMSH / TRMBF / TRSKL / TRANM 字段与四元数格式参考 [Pokémon Switch Model Importer](https://github.com/ChicoEevee/Pokemon-Switch-Model-Importer-Blender)。大狼犬 BNTX 离线解码使用 [BNTX Extractor](https://github.com/aboood40091/BNTX-Extractor)，BC5 法线 Z 分量由单位长度恢复。

## 骨架与贴图处理

两只宠物各用自身 TRSKL 与对应 TRANM。骨架父级从零编号，原始 XYZ 欧拉角按 Three.js 的 ZYX 顺序组合。大狼犬构建器逐骨骼比对文件内逆绑定矩阵，误差超过 `0.0001` 时中止构建。基础姿态与入场头部姿态共用拓扑，并保持同一原点；模型按基础姿态最低点落地。

两只宠物统一复用花花材质：首页为金属，二级聚焦页最终为线框，倒影同步切换。原始 PNG 贴图保留在 `scripts/assets/` 作离线资料，运行时不下载或解码原色贴图。花花首页使用 `00281_sleep01_loop` 睡姿及尾巴弯曲，二级页过渡至 `00001_battlewait01_loop` 战斗姿并保留歪头；小黑使用 `00271_rest01_loop` 官方坐姿并仰头。

小黑首页 `displayScale` 仍为 2.6。二级页通过相机距离适配，以花花最终姿态的实际投影最大尺寸作为基准，小黑通过 `focusScale: 1.15` 将最终投影放大 15%，首页物理缩放保持不变。模型取景位置以原构图（桌面 18%，手机水平居中）为基准；花花最终位置通过 `focusOffsetX: 0.01` 向右偏移视口宽度的 1%，小黑沿用原构图。只有切换和构图变化时计算投影，静止时不持续运算。

每只宠物独立维护 `rotationY.home`、`rotationY.focus` 与 `focusPitch`，初始 / 最终朝向分别为：花花 -35° / -35°，小黑 45° / 57°；小黑初始朝向由原 55° 减去 10°，最终朝向由原 -15° 调整至 57°，按固定镜头方向将原朝左角度对称调整为朝右，并保留正面可见。聚焦镜头俯仰分别为 -8°、-7°。镜头方位固定 -70°，独立于模型旋转，避免调整模型时镜头也绕到背面。聚焦和返回时按各自数据切换朝向。倒影仅由父组翻转一次。

## 构建与性能

复用已运行的本地 Vite 服务：

```sh
# 修改模型或姿态后更新几何与内容版本
# 不启动或停止开发服务
yarn build:flora-pets
```

文件名的 `sleep` 为兼容历史缓存保留，元数据 `pose` 标识最终姿态。原始输入在 `scripts/assets/`，运行时只读取 `public/models/*-sleep.json`、`*-sleep.bin.gz`，不携带未使用的 UV 或原色图集。模型首次选择时加载，会话内复用下载与解码结果。资源就绪后淡出 220ms、替换网格、淡入 420ms，镜头在 1050ms 内轻微拉远再收回，模型旋转与姿势变形同步执行。旧 GPU 几何及时释放，场景卸载释放剩余资源。运行时不加载完整骨架；入场结束后复用限频鼠标采样，通过 yaw 10° / pitch 8° 的头部差量变形目标平滑跟随鼠标，触屏移动不触发转头，静止后停止绘制。两只宠物的水平、垂直跟随目标均放大至 2 倍，复用既有变形目标。头部横向跟随按镜头方位、模型旋转与原始网格头部朝向共同转换，避免小黑朝向调整后左右反转。实体、线框、深度层和倒影保持一致。

异步切换采用版本号保护，迟到结果不覆盖最新选择；下载失败保留当前宠物，支持重试。

## 小黑眼部磨平与坐姿

小黑仅删除眼球与眼窝凹凸，使用独立的 `smoothMightyenaEyes` 按外皮有向边重新封口，并平滑眼窝接缝法线，旧面部处理器已删除。保留口腔、牙齿、下颌、脸颊与尖爪，不收合下颌。构建入口 `prepareMightyenaGeometry` 仅执行眼部处理，不再保留修改嘴部和爪子的分支；元数据 `faceEdits.eyesRemoved` 为 `true`，爪部删除数量仍为 0。基础、仰头及鼠标跟随姿态均应用相同眼部处理。

继续采用官方 `00271_rest01_loop` 坐姿动画，保留当前仰头入场、鼠标跟随、模型朝向、金属 / 线框材质和页面构图。原文件位于 `scripts/assets/mightyena/pm0262_00_00_00271_rest01_loop.tranm`。

## 架构与缓存

- `bakedPetModel.ts` 统一两只宠物的类型、并发加载和 gzip 解压；`cachedModelLoader.ts` 保留下载去重、整批超时与失败重试。场景独立创建及释放 GPU 几何。
- `scene/petFocusCamera.ts` 独立计算聚焦取景：顶点使用连续数值缓冲；二分距离使用相机基底上的投影。每个几何体只缓存最近构图，视口、旋转、缩放、位置或参考模型变化时重算。
- 诊断投影按几何体和组合矩阵缓存，头部跟随不再重新扫描整模型。实体、线框、深度层与倒影使用固定网格列表同步变形，避免逐帧重建列表。
- 小黑的 UV 只在离线减面时约束接缝，完成减面后移除；运行时输出不含 UV 和贴图元数据。无用的三个 WebP 图集及生成脚本已删除，原始 PNG 与 BNTX 输入保留。
- 眼窝封口通过端点 Map 查找后续有向边，边界追踪由平方复杂度降为线性；四个构建姿态共享原始文件下载。此项改善构建耗时，不算页面运行时收益。

## 三模型统一几何面块造型

- 路卡、花花、小黑统一经过离线 `facetModelGeometry.mjs` 处理：按全部姿态／骨骼权重焊接接缝，单次受限平滑，再进行轮廓保护减面；宠物目标约为输入面数的 55%，路卡已有较强减面且薄壳较多，目标保守设为 90%。固定各高度层的轮廓支撑点、极值、开放边界及头颈混合权重；平滑最大位移不超过模型尺度的 0.4%。
- 新增约束涵盖花花／小黑的基础、最终、yaw 和 pitch 目标，以及路卡的头部和低头权重，三种材质层及倒影保持同一拓扑。
- 三个模型统一启用 `flatShading`，面法线由变形后的三角面求导。高光参数恢复原值：粗糙度 0.09、清漆粗糙度 0.08、环境反射基础强度 1.8／悬停增量 0.8、清漆基础强度 0.45／悬停增量 0.25。保留当前配色、环境旋转、模型朝向、大小、位置及双倍跟随幅度。
- 当前三角面：路卡 1527、花花 1110、小黑 1316。`faceting` 元数据记录该阶段的输入／输出面数、平滑顶点与减面误差；路卡原 `stats` 中头部／颈部细分统计属于此前预处理阶段，最终总面数以 `stats.simplifiedFaces` 为准。
- 宠物重建只在传入原始采样时执行面块化，重新压缩现有输出不会重复平滑或减面。路卡构建入口每次从原始模型重建。
